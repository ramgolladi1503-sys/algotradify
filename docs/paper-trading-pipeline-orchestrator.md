# Paper Trading Pipeline Orchestrator

PR 92 adds a minimal in-memory paper trading pipeline orchestrator.

## Purpose

The paper truth foundation now has:

```text
journal -> reducer -> ordering guard -> rebuild CLI -> reconciliation report
```

This PR adds the first controlled paper-cycle pipeline that wires existing paper-only components together without persistence, API, UI, dashboard, runtime wiring, or broker execution.

## Pipeline

```text
build_paper_order_intent
  -> build CREATED / ACCEPTED / OPEN lifecycle evidence
  -> simulate_paper_fill from controlled quote
  -> convert outputs to canonical paper events
  -> guard_paper_event_ordering
  -> reduce_paper_events
  -> return pipeline result
```

## Statuses

```text
COMPLETED
NOOP
BLOCKED
```

`COMPLETED` means all required stages ran and the reducer derived state.

`BLOCKED` means input validation or one of the pipeline stages failed closed.

`NOOP` is reserved for a future scoped cycle where no candidate is intentionally processed. PR 92 does not build no-trade orchestration.

## Scope boundary

This is in-memory only.

This PR does not add:

```text
journal append
persistence layer
API endpoint
UI/dashboard
runtime wiring
broker execution
LIVE orders
strategy/provider work
ML/ranker work
reconciliation persistence
```

## Safety contract

Every pipeline result exposes:

```text
paper_only=true
read_only=true
is_order_action=false
broker_api_called=false
real_order_id=null
```

Canonical events generated by the pipeline also preserve:

```text
paper_only=true
is_order_action=false
broker_api_called=false
real_order_id=null
```

## Blocking behavior

The pipeline fails closed on:

```text
missing cycle_id
missing top executable input
missing execution safety input
missing controlled quote input
unsafe order-action flags
broker_api_called=true
real_order_id present
blocked intent creation
blocked lifecycle transition
blocked fill simulation
invalid canonical event conversion
ordering guard blocker
state reducer blocker
```
